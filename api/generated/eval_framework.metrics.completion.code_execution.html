eval_framework.metrics.completion.code_execution.python_tests module¶

Checking Python code against a test suite in the sandbox (BigCodeBench-style).

execute_python_code_with_tests merges the code with its tests (e.g. unittest_merge_snippets), pip-installs the external packages its imports need (get_external_dependencies), runs it via run_python_code, and turns the output into an ExecutionResult (e.g. parse_unittest_output).

eval_framework.metrics.completion.code_execution.sandbox module¶

Running code in Docker sandboxes (via llm_sandbox).

  • run_python_code: for a Python snippet, optionally with pip packages, a custom image/Dockerfile, or input files

  • execute_in_default_image: for a single file in a language llm-sandbox supports natively (SupportedLanguage)

  • execute_in_custom_image: for everything else, e.g. a language llm-sandbox doesn’t support, another image, extra files next to the code.

eval_framework.metrics.completion.code_execution.sandbox.execute_in_custom_image(full_code, cfg, timeout, extra_host_files=None, runtime_configs=None)[source]¶

Copy code (and optional extra files) into a language-specific Docker image and run.

We open a SandboxSession with a dummy lang (SupportedLanguage.PYTHON) so that llm-sandbox sets up the container plumbing, but we never call session.run(). Instead we write the code to a local temp file, copy it into the container with copy_to_runtime, and drive each compile/run command with execute_command.

Each invocation gets a unique UUID-named directory inside the container so that concurrent calls never clobber each other’s source files or build artefacts.

extra_host_files maps container filename -> host path for any additional files that should be copied into container_dir before the commands run (e.g. dependency jars).

runtime_configs is passed to the container pool (e.g. {"mem_limit": "1g"}).

Return type:

Module contents¶

Metrics that score code by executing it, and the infrastructure they share.

Infrastructure:

  • sandbox: running code in Docker containers (Python snippets, or any language in a language-specific image).

  • python_tests: checking Python code against a test suite (merging, dependency installs, output parsing).

Metrics:

  • python_assertion: Python code whose last printed token must be True (HumanEval, MBPP, LBPP).

  • pass_at_one: pass@1 of Python code against a unittest suite (BigCodeBench).

  • multipl_e_assertion: MultiPL-E’s language-native test harnesses, in a language-specific image.
