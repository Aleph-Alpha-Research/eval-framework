eval_framework.tasks.base.resolve_overwrite_subjects(custom_subjects, accepted_subjects, task_name)[source]¶

Restrict accepted_subjects to the ones requested via –task-subjects.

A subject matches a token when their parts agree position by position, where “*” matches any one part – so “DE_DE,*” selects every German subject and “*” selects every scalar subject.

final class eval_framework.tasks.dataset_loading.Subset(inner, keep, description=None)[source]¶

Bases: DatasetPolicy

Restricts another policy’s dataset to the rows for which keep returns true, in every split.

A benchmark whose items are a row-filtered subset of a larger dataset (e.g. GPQA’s diamond subset, HLE’s natively-multiple-choice subset) wraps the base policy in a Subset. description names that subset for the rendered dataset docs; without it the docs only note that some rows are dropped.

Pinned Hugging Face dataset revisions.

class eval_framework.tasks.lazy.Lazy(id, load)[source]¶

Bases: Benchmark

A Benchmark that defers producing the real benchmark until first use.

Holds an id and a load thunk returning the wrapped Benchmark; every other call is delegated to that benchmark, which is built (and memoized) on first access. This keeps Lazy independent of any concrete task type — the thunk owns whatever loading (e.g. importing a module) the wrapped benchmark requires.

Bases: ABC

A benchmark is used to provide means of measuring model performance in a domain.

Benchmark act as factories for Eval. They bind all the a prior known information and enrich it with the arguments provided at runtime to create concrete instances of Eval which are used to provide measurements of the models performance.

eval_framework.tasks.task_style module¶

Task-style helpers and strategy classes for choice-based evaluation tasks.

This module provides injectable styling strategies — MCStyle, ClozeStyle, MCCompletionStyle and BPBStyle — that render one choice item (question plus answer options) into the prompt text, answer cue, scored candidates and ground truth. The styler also declares the response type, metrics and metadata of its style.

Quick-start¶

A choice-based benchmark pairs a ChoiceReader (item -> raw question, choices, correct index) with a styler via ComposedBenchmark.choice, which drives both the scored sample and the few-shot demonstrations from the same pair:

benchmark = ComposedBenchmark.choice(
    id="MyBenchmark",
    reader=MyChoiceReader(),
    styler=ClozeStyle(question_prefix="Question: ", cue_text="Answer:"),
    sample_split="test",
    fewshot_split="train",
    dataset_policy=Pinned("my/dataset"),
)

Task families with MC, Cloze and BPB variants share the reader and differ only in the styler each variant’s builder injects.

class eval_framework.tasks.task_style.IdkStyle(inner, abstention_option)[source]¶

Bases: TaskStyler

Adds an explicit abstention option (e.g. “I do not know”, “?”) to a base styler’s candidates.

Use this when a benchmark rewards calibrated abstention over confident guessing: it scores the real answers together with the abstention option and reports confidence-aware metrics. Everything else — the prompt formatting and the abstention preamble (via the inner styler’s initial_prompt) — is the inner styler’s; wrap any base styler, so both multiple-choice (abstain with an extra letter) and cloze (abstain with an extra full answer) tasks are supported.

Parameters:

  • inner (TaskStyler) – The base styler doing the prompt formatting, preamble, and real-answer scoring.

  • abstention_option (str) – The abstention completion scored alongside the real choices, e.g. " I do not know" (cloze) or " ?" (multiple-choice).

class eval_framework.tasks.task_style.MCCompletionStyle(question_prefix='Question: ', cue_text='Answer:', space_prefixed_labels=False)[source]¶

Bases: TaskStyler

Multiple-choice prompt style with generative completion output.

Prompt formatting is identical to MCStyle (choices shown in prompt), but ground truth is the full answer text (for example "Paris" instead of "D"). Responses are generated via ResponseType.COMPLETION and scored with AccuracyCompletion.

This style is useful for instruction-following or CoT prompts where the model is expected to generate an answer text rather than be scored via loglikelihood over fixed label candidates.

Parameters:

  • question_prefix (str) – Prepended to the raw question (default "Question: ").

  • cue_text (str) – Assistant cue after the prompt (default "Answer:").

  • space_prefixed_labels (bool) – When True, each option line starts with a space (" A. choice" — OLMES-style). Default False.

Assembled prompt example (default settings, 4 choices):

"Question: What is the capital of France?\nA. Munich\nB. Stuttgart\nC. Berlin\nD. Paris\nAnswer:"

Ground truth: "Paris"

Extract the Python source from a chat-style LLM response that wraps its answer in markdown code fences.

The response is expected to contain a single Python solution (e.g. HumanEval, MBPP, BigCodeBench). The first matching fenced block is returned, tried in this order: a `python block nested inside a ```markdown block, a plain ```python block, a ```markdown block, and finally any ` block. If the response contains no fences at all, it is assumed to be raw code and returned unchanged.

str
